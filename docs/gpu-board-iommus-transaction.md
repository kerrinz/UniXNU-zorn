# Pure IOMMU property parser output transaction repair

The exact retained NativeAdrenoBoard header promises that parseIommus preserves its stream-ID output on failure. The implementation wrote each SID immediately after validating that entry, so a later zero phandle or oversized SID returned an error after exposing an earlier prefix. This is a file-property parsing defect; it does not establish a K80 stream route or mapping authority.

Eight actual synthetic-byte reproductions cover a second-entry bad phandle and SID above 0xffff for each supported one-through-four specifier-cell layout. The original overwrites the first output element in all eight cases. An independent UNAPPLIED candidate validates the full property before its copy pass; all eight failures now leave the complete SID buffer unchanged. Existing count=0-on-failure semantics stay unchanged. Four new valid layout controls preserve order, zero and 0xffff SID values and an adjacent output canary. These are synthetic file values, never hardware identifiers or leases.

Host ASan/UBSan passes. Only the changed candidate was compiled into one isolated iOS17 ARM64 object using the existing actual XNU recipe and real target headers. The host scalar status shim was not a target include and models no provider or object. The object was not linked or executed. parseReg is byte-for-byte unchanged; it never promised transactional window output, and K80 DescribeResources already uses a local temporary to discard its partial failure writes. No parseReg patch or old suite rerun is justified here.

Catalog files, submodule pins, the 32 original patches and 8 profiles remain untouched. This new patch is independent and unselected. The parser header/source and new object evidence are archived separately; no old proof was requalified. No native allocation/getter/service start/stop/MMIO/USB or device operation executed.

The current service caller gates use of the parsed SID list on parser success, so this review does not claim a demonstrated hardware misuse at that caller. A separate pending source lifetime question exists there: the owned copyMatchingService result named smmu is released before a later bringup branch refers to smmu. Review all ownership paths and existing patches before claiming a defect or proposing an isolated fix. Do not execute the branch, select bringup, construct native peers or use MMIO as a test.
