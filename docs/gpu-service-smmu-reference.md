# Copied SMMU service reference lifetime

The exact retained NativeAdrenoService start() receives a caller-owned reference from IOService::copyMatchingService. IOService.h documents that the caller must release it. The local smmu pointer is not reassigned or retained elsewhere in the reviewed function. Originally its reference was released after property logging, before a later optional bringup branch casts and dereferences that same pointer. Publication in the registry is not a stable owned reference against concurrent removal. This is a source lifetime defect, not an observed phone use-after-free.

An independent UNAPPLIED candidate moves that single release after the entire synchronous bringup block and before the two remaining returns. All earlier returns precede acquisition. There are no new retain calls, fields, parameters, selectors, methods or object layout changes. Acquisition and all bringup/callback/MMIO bodies remain unchanged. Source-derived traces show release-before-cast/window-use in the original and an owned reference through every such synchronous use in the candidate. Four source controls reject early/missing/double release and a newly introduced exit before cleanup. These checks do not construct or run an IOService/provider model.

Only the changed nonoptional Service candidate was compiled with the retained exact iOS17 recipe and real dependencies. The standalone object was not linked or executed; optional firmware/vote/CommandDB generation remains absent. No whole-driver or frozen role-API compile was retried, and no API stubs or flags were changed. The existing metaclass initializer is compiled code and was never executed.

Retaining the object does not prevent service termination, retain its mappings, establish quiescence or authorize SMMU/MMIO. The earlier stop/map-lifetime restrictions remain unresolved. This patch does not make the optional bringup branch safe to execute or select it for K80. The original catalog, original 32 patches and old source profiles remain unchanged; this candidate is not combined with the earlier CP-cookie or parser candidates.
